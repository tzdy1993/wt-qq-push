# 战争雷霆官方资讯 → QQ 群

抓 [warthunder.com/zh/news](https://warthunder.com/zh/news/) 的最新新闻与开发日志，自动推到 QQ 群。

走 **QQ 机器人开放平台**官方 API，不需要挂 QQ 客户端、不需要小号、不需要服务器常驻。

## 它长什么样

一条消息，图 + 标题 + 摘要 + 可点按钮：

```
┌─────────────────────────────┐
│  [官网封面图 600×338]        │  ← markdown 内嵌
│  【开发】H-39：夭折巨兽      │  ← ## 渲染成大字加粗
│  德国远洋海军科技树全新顶级   │
│  战舰——现实中未能完工的…     │
│  [  📖 阅读全文  ]           │  ← 可点按钮，跳官网
└─────────────────────────────┘
```

用 `msg_type=2` markdown + `keyboard` 跳转按钮。

**图片语法必须带尺寸**：`![封面 #600px #338px](url)`。写成 `![](url)` 只会渲染出一片空白，这是踩过的坑。

`QQ_PUSH_MODE` 控制形态：

| 值 | 效果 |
|---|---|
| `markdown`（默认） | 一条 markdown（含封面图）+ 按钮 |
| `both` | 封面图单独一条 + markdown，两条 |
| `text` | 纯文本一条，不带按钮 |

其他可调项：`QQ_MD_IMAGE=0` 关掉内嵌图，`QQ_MD_IMG_W` / `QQ_MD_IMG_H` 调尺寸。

## 文件

| 文件 | 作用 |
|---|---|
| `wtnews.py` | 抓官网新闻 + 更新日志列表页，解析标题 / 封面 / 摘要 / 日期 |
| `forum.py` | 抓官方论坛中文区的官方主题，按 gid=47 过滤，按标题剔除官网镜像 |
| `qqbot.py` | QQ 机器人 API 封装：token 管理、群消息、素材上传、按钮 |
| `main.py` | 主流程：抓取 → 去重 → 渲染 → 发送 → 记账 |
| `get_group_openid.py` | 一次性脚本，拿群的 `group_openid` |
| `state.json` | 已推送的新闻编号（去重靠它） |

## 本地跑

```powershell
pip install -r requirements.txt

# 看效果，不发消息
python main.py --dry-run

# 首次：把现有新闻全部标记为已推送，避免一上线就刷屏
python main.py --init

# 正常推送一次
python main.py

# 常驻，每 15 分钟一轮
python main.py --loop 900
```

凭证走环境变量：

```powershell
$env:QQ_APPID="..."
$env:QQ_SECRET="..."
$env:QQ_GROUP_OPENID="..."
```

## 部署到 GitHub Actions（零服务器）

1. 把项目推到 GitHub 私有仓库
2. `Settings → Secrets and variables → Actions`，加三个 secret：
   - `QQ_APPID`
   - `QQ_SECRET`
   - `QQ_GROUP_OPENID`
3. `Settings → Actions → General → Workflow permissions` 选 **Read and write permissions**（要提交 `state.json` 回去）
4. 先手动跑一次 `WT News → QQ`（`workflow_dispatch`）验证，之后每 15 分钟自动跑

> 私有仓库每月 2000 Actions 分钟。30 分钟一轮、每轮约 50 秒，月耗约 1200 分钟，够用。

## 首次接入 checklist

1. 在 [QQ 开放平台](https://q.qq.com/) 创建机器人，完成个人主体认证
2. 手机 QQ 把机器人拉进群
3. **群主**在手机 QQ「群机器人 → 设置权限」里开启 **允许主动推送消息**
   —— 不开会一直返回 `40034105 主动消息失败, 无权限`
4. 群里 @ 机器人一句话，用 `get_group_openid.py` 抓 `group_openid`
5. 发一条测试消息验证

## 踩过的坑

| 现象 | 原因 |
|---|---|
| `100016 invalid appid or secret` | AppSecret 复制不全。标准长度 **32 位**，去后台重置后走复制按钮 |
| `11255 请求的资源不存在(用户/群已注销)` | 把群号当 `group_openid` 传了。两者不是一个东西 |
| `40034105 主动消息失败, 无权限` | 群主没开「允许主动推送消息」 |
| 中文抓出来是乱码 | 官网是 UTF-8，`requests` 自动猜会猜错，必须 `r.encoding = "utf-8"` |
| 首次上线刷屏 | 忘了跑 `--init` |
| `msg_type=0` 或 `7` 带 `keyboard` 没反应 | 按钮只能挂在 **markdown 消息**上，纯文本和图片消息的 keyboard 会被客户端忽略 |
| markdown 里 `![](url)` 图片不显示 | QQ 群 markdown 不允许外链图片，只留一片空白 |
| 表格、代码块这类 markdown 不渲染 | QQ 群只认标题/加粗这类基础语法 |

## 三个数据源

| 源 | 地址 | 独家内容 | 去重键 |
|---|---|---|---|
| 官网新闻 | `warthunder.com/zh/news/` | 开发日志、活动、商店 | `2878` |
| 官网更新日志 | `warthunder.com/zh/game/changelog/` | 版本更新、服务器更新 | `cl:729` |
| **官方论坛中文区** | `forum.warthunder.com/c/national-communities/86-category/86` | **分房权重变动、测试服开启、官方爆料、开发进行时** | `f:360169` |

三个编号空间彼此独立。

论坛源只认 `National Coordinator`（`primary_group_id = 47`）发起的主题——中文区只有 `Monika_in_action` 和 `Autumn_Maple秋枫` 两个人是这个身份。判断依据是组 ID 而不是用户名，以后换人只要工牌不变就自动生效。

中文区 94% 的内容是官网新闻的翻译，用标题相似度剔除（阈值 0.45），只推真正独有的那部分。实测 35 条官方主题里，33 条被识别为镜像，剩下 2 条是独家。

## 时间同步情况（实测）

| 对比 | 结果 |
|---|---|
| 官网 → 论坛英文区 | **延迟 0.0 小时**（Steam 时间戳验证，同时发） |
| 官网 → 论坛中文区 | 延迟 **8~51 分钟** |
| 官网新闻 → 官网更新日志 | 同一天，官网只有日期精度，无法测更细 |

**注意**：官网页面的日期只精确到「天」，而且详情页的 `.date` 是**评论区时间**不是发布时间。所以任何基于官网日期的小时级推算都是错的，本项目已彻底废弃时间判断，只用编号。

## 为什么图片不会裂

最初的做法是直接在 markdown 里写官网的公网图片地址。**会偶发裂图**——markdown 图片由 QQ 平台去外网下载转存，拉取失败就留一张裂图（实际遇到过：2879 挪威空军那条）。

改成走**素材管理**接口，先把图片存进 QQ 自己的存储，再引用：

```
POST /v2/media-images/prepare   → upload_id + presigned_url
PUT  presigned_url              → ETag
POST /v2/media-images/complete  → qqbot-media://image/v1/<token>
```

markdown 里写 `![封面 #600px #338px](qqbot-media://image/v1/...)`，发送时平台直接取内部副本，不依赖外网。

| 项目 | 说明 |
|---|---|
| 单图上限 | 10MB（官网封面 80~200KB，远低于） |
| 素材配额 | 单机器人 100 张，快满时自动删最旧的（保留 80） |
| 有效期 | 90 天滑动过期，被消息引用就顺延 |
| 转存失败 | 本条降级为纯文字，绝不发裂图 |

代价是每条消息多 4 次请求（下载图 / prepare / PUT / complete），约 2~3 秒。

不要图片：`QQ_MD_IMAGE=0`，两类消息都变纯文字。

官网页面上有日期，但藏在两个不同位置，都抓了：

| 源 | 日期来源 | 格式 |
|---|---|---|
| 新闻 | 详情页 `<div class="date">` | 相对时间「7 小时以前」 |
| 更新日志 | 列表页卡片 `.widget-meta` | 绝对日期「2026 年 10 月 30 日」 |

有了日期就能做三道过滤，任何一道拦住就不会刷屏：

**1. 编号过滤** — 比「已知最大编号」还小的条目，判为历史积压直接跳过，连详情页都不抓。

```
[skip] 新闻 2872 不晚于已知最新 2879，判为历史积压
```

**2. 时间过滤** — 超过 `QQ_MAX_AGE_HOURS`（默认 24 小时）的不发，只标记已读：

```
[stale] 跳过 cl:729《2026 年 10 月 30 日服务器更新》（281 小时前发布）
```

**3. 抓 2 页兜底** — 新闻每页 18 条、更新日志每页 12 条，各抓 2 页留缓冲。单页失败只告警不中断，某页无新增即停止翻页。

效果：Actions 停摆三天再恢复，也只会推最近 24 小时内真正的新内容，陈年积压全部静默标记为已读。

想放宽或收紧：

```bash
QQ_MAX_AGE_HOURS=48    # 放到 48 小时
QQ_MAX_AGE_HOURS=6     # 只要 6 小时内的
```

真要补抓历史（比如首次部署想补一批），用 `--pages 5` 配合 `QQ_MAX_AGE_HOURS` 调大。

## 已知限制

- **个人主体机器人只能在「自己是群主 / 管理员」的群里用**，不支持公开添加、不能上架机器人市场
- 主动消息频控：单群 20 条/分钟、1000 条/群/天，对新闻推送完全够
- 链接实测**不需要**配 URL 白名单就可以直接发（`warthunder.com`）
- 官网改版会让 `.widget` / `og:` 这类选择器失效，`wtnews.py` 里集中改一处即可

## 为什么是「markdown + 按钮」

试过的所有组合，实测结果：

| 组合 | 文字排版 | 按钮 | 图片 |
|---|---|---|---|
| `msg_type=0` 纯文本 | ✅ | ❌ | ❌ |
| `msg_type=2` markdown | ✅ | ✅ | ✅（**必须带尺寸** `![alt #600px #338px](url)`，只写 `![]()` 出空白） |
| `msg_type=7` 图片 | ❌（`content` 被忽略） | ❌ | ✅ |
| 结构化卡片 Ark | — | — | —（群聊「发 ❌」，只能收） |

结论：**markdown + keyboard 一条消息就能同时做到「图 + 文字 + 可点链接」**，这是唯一同时满足三个要求的组合。

`card.py` 里的卡片渲染（把文字画进图）留着当备用——只有它能在图上排出任意版式，但图上链接点不了。日常用不上。

## 消息条数预算

一条新闻 = 2 条主动消息。群聊主动消息限 1000 条/群/天，够发 500 条新闻，战争雷霆一天最多十几条，绰绰有余。

如果介意一个更新季连发好几条占版面，可以用 `state.json` 的 `pushed` 只推「开发日志」类（官网 `?tags=开发` 支持按标签过滤）。
